## 1. 원본 제안 한 줄 요약

Community를 게시판이 아니라 **"다른 엔지니어가 어떻게 판단했는지 배우는 공간"** 으로 정의하고 `Drill 해결 → 공유 → 다른 접근 비교 → 토론 → 다시 Drill` 루프를 만들자는 제안입니다. 원본이 꼽은 핵심 5개는 **Solution Compare · Architecture Review · Incident Review · Fork My Run · Weekly War Game** 이고, 그중 Fork My Run("그럼 같은 상태에서 직접 해봐")을 가장 강하게 권합니다.

## 3. 이 계획안이 취하는 입장

1. **모든 커뮤니티 객체는 시나리오에 붙어 있다.** ADR-0040은 토론을 "시나리오 버전당 스레드"로 제한했고, 이 계획도 같은 선을 지킵니다. 원본의 Architecture Review("내 설계를 올려 리뷰 요청")와 실제 경험 Postmortem 공유는 **시나리오 밖 자유 게시판**이 되므로, 전자는 "공개 풀이에 붙는 리뷰"로 바꾸고 후자는 받지 않습니다. 시나리오에 붙어 있어야 채점 기준·지표·완료 게이트라는 맥락이 함께 옵니다.
2. **비교는 구조화된 데이터로 한다.** 설계 비교·"나와 다른 설계"는 LLM 요약이 아니라 `system_topologies.graph`(노드 kind · trait 값 · 엣지)의 결정론적 차이로 계산합니다. LLM 설명은 그 차이를 입력으로 받는 선택 기능입니다.
3. **ADR-0041 게이트가 비교의 전제다.** 공개 풀이는 그 시나리오를 완료한 사람만 봅니다 — 즉 **열람자는 항상 자기 풀이를 갖고 있습니다.** 그래서 "나와 비교", "나와 다른 설계" 정렬이 모든 열람자에게 성립합니다. 게이트를 약점이 아니라 설계의 근거로 씁니다.
4. **진행 중 정보는 공개하지 않는다.** 1차 기획의 공개 범위 원칙(실패 이력·약점·진행 중 상태 비공개, 랭킹 숨김 사용자는 새 공개 노출에서도 제외, 조직 시나리오 제외)을 새 기능 전부에 적용합니다.
5. **실시간은 여전히 폴링이다** ([ADR-0026](adr/0026-game-day-spectating-is-scoped-by-shared-org-membership-and-still-defers-websocket.md)).

### 하지 않는 것

| 하지 않음 | 이유 |
|---|---|
| Follow · For You 피드 · 범용 SNS | 1차 기획 안티골 유지. 개인화는 "내가 완료한 Drill"로 충분 |
| 시나리오 밖 자유 게시판(실제 장애 공유, 자유 설계 리뷰 요청) | §3-1 |
| 직급·회사 기반 Expert 인증 | 검증 수단 없음. 평판(C14)이 생기면 활동 기반으로 재검토 |
| 좋아요 수 기반 정렬을 기본값으로 | 원본도 경계한 인기투표화. 기본은 "나와 다른 설계" |

### C7 — 토론 마무리

진행 중인 토론 슬라이스를 "운영 가능한 상태"로 닫는 작업입니다. 1차 기획이 "토론은 모더레이션 운영을 시작시킨다"고 경고했는데, 지금은 API만 있고 운영 화면이 없습니다.

- **관리자 모더레이션 화면**: 기존 `/admin`에 신고된 토론 목록 + 숨김/복원 (`GET /admin/discussions/reported`, `PUT /admin/discussions/{id}/hidden`은 이미 있음).
- **노출 위치 확대**: Drill 개요 우측 레일("토론 N · 최근 질문"), 리포트 하단, 개념 상세의 "이 개념이 나오는 시나리오의 토론"([LEARNING_EXPANSION_PLAN.md](LEARNING_EXPANSION_PLAN.md) L4). 지금은 `/community`에서만 들어갈 수 있습니다.
- **스포일러 표시**: 작성자가 `풀이 내용 포함`을 체크하면 미완료자에게 흐림 처리 + "완료 후 보기". 인용 풀이의 잠금(이미 구현)과 같은 게이트를 본문에도 씁니다.
- **답글 1단계**: `parent_id` — 질문에 대한 답이 스레드 끝에 흩어지지 않게. 더 깊은 중첩은 만들지 않습니다.
- **글 종류 태그**: `질문 · 설계 · 대응 · 인사이트` 정도. 원본의 7종 입력 템플릿은 과합니다 — 태그는 필터용이고 템플릿은 C10 리뷰 유형에서만.
- **제품 피드백**: GitHub Issues 링크를 앱 푸터의 "제품 피드백 ↗"으로 복원(원본 §23 — 학습 커뮤니티와 제품 개발 커뮤니티의 분리).

**완료 기준**: 통합 테스트(답글 조회 순서, 스포일러 글이 미완료자 응답에서 본문 대신 잠금 표시, 숨김 글 미노출), 관리자 화면에서 신고 → 숨김 → 목록에서 사라짐 실브라우저 확인.

### C8 — 풀이 자동 요약 + 설계 비교

- **자동 요약 카드**: 공개 풀이 상단에 기존 데이터로 만든 요약 — 캔버스 다이어그램(Mermaid), 기본값에서 바꾼 trait(= 핵심 결정: `Redis TTL 10→60`, `single-flight 켬`), 결과(점수 · MTTD · MTTR · 적용 액션 순서), 역량 카테고리 점수. 작성자는 **메모 한 칸만** 쓰면 됩니다(원본 §4 "사용자는 설명만 추가"). 새로 생성하는 데이터는 없습니다.
- **설계 비교** `GET /writeups/{sessionId}/compare` (열람자 자신의 같은 시나리오 최고 세션과): 두 `system_topologies.graph`의 차이 —
  - 노드 kind 집합 차이 (`상대만: queue, read replica`)
  - 같은 kind의 trait 값 차이 (`consumerCount 4 vs 16`)
  - 결과 차이 (점수, MTTR)
  - "가장 큰 차이" = 결과 차이가 가장 큰 축에 해당하는 trait
- **나와 다른 설계 정렬**: 풀이 목록의 정렬 옵션 `나와 다른 순`(기본값) / 점수 / 최신. 거리 = kind 집합의 Jaccard 거리 + 정규화한 trait 차이. 원본 §6의 확증 편향 감소 목적.
- **한계**: 캔버스를 쓰지 않고 텍스트로만 답한 세션은 토폴로지가 없어 비교·거리 계산에서 빠집니다(요약 카드만 표시). 캔버스 사용률이 낮으면 이 슬라이스의 가치가 줄어들므로 착수 전 공개 풀이 중 토폴로지 보유 비율을 확인합니다.
- LLM 설명("두 설계의 가장 큰 차이는 발급 확정 시점입니다")은 위 구조적 차이를 입력으로 받는 선택 기능이며, 풀이 쌍마다 호출하면 비용이 커서 2차로 미룹니다.

### C9 — Fork My Run

- 공개 풀이의 리플레이 임의 시점에서 `[여기서 내가 해보기]` → **그 사람의 설계 trait + 그 시점까지의 액션 이력**으로 포크 상태를 만들고 내가 이어서 대응합니다. 결과는 원래 풀이와 나란히(`원래 MTTR 14분 32초 / 내 포크 7분 18초`).
- 메커니즘은 Drill M6(Counterfactual)과 **동일**합니다 — 포크는 영속 세션이 아니라 Redis 임시 상태이고(M6의 ADR 후보를 그대로 물려받음), 규칙 기반 세션만 지원합니다. 실제 인프라 풀이에는 버튼을 표시하지 않습니다.
- 포크 결과는 저장하지 않습니다. 공유하고 싶으면 토론에 "포크 결과"로 글을 쓰는 것까지(결과 수치를 첨부).
- 추가로 노출되는 정보가 없습니다 — 액션 이력은 이미 공개 풀이 리플레이로 보이는 것입니다.

### C10 — 앵커 리뷰

- 공개 풀이에 **위치가 있는 댓글**을 답니다: `writeup_comments(session_id, anchor_type, anchor_ref, kind, body)`.
  - `NODE` — 캔버스 노드 ID에 고정(원본 §7 "Architecture Node 단위 댓글")
  - `TIMELINE` — 인시던트 타임라인의 특정 액션(또는 관측 계획안 O0-b의 조사 이벤트)에 고정(원본 §9 "여러분이라면 14:04에 무엇을 했을까요?")
  - `NONE` — 풀이 전체
- `kind`는 리뷰 유형 `질문 · 리스크 · 제안 · 대안 · 트레이드오프`(원본 §8). "좋네요"류를 줄이는 장치입니다.
- 열람·작성 모두 ADR-0041 게이트(완료자만). 풀이가 비공개로 전환되면 댓글도 함께 숨깁니다(1차 기획 §6.2에서 정한 대로). 신고·숨김은 C7의 운영 화면을 재사용합니다.
- 원본의 "리뷰 요청"은 공개 풀이의 작성자 메모(C8)에 질문을 적는 것으로 대신합니다 — 별도 요청 객체를 만들지 않습니다.

### C11 — Community 홈 재구성

```
Community
├ 내 Drill에서        ← 내가 완료한 시나리오별: 새 풀이 수 · 새 토론 수 · [비교하기]
├ 이번 주 활발한 토론   ← 최근 7일 글 수 기준, 스포일러 글은 제목만
├ 주목할 풀이          ← 앵커 리뷰가 많이 달린 풀이 (미완료 시나리오는 잠금 + 편 수)
├ 랭킹                ← 기존 RankingPanel
└ 시나리오 전체        ← 공식 + 마켓플레이스 (기존)
```

- "새 것"의 기준 시각은 localStorage의 마지막 방문 시각 — 편의 기능이라 서버에 저장하지 않습니다.
- 토론 화면 우측에 관련 개념(시나리오 도메인 → 개념의 `relatedDomains` 역참조), 개념 화면에 관련 토론(C7) — 원본 §21의 양방향 연결.

### C12 — 주간 "What Would You Do?"

- 원본은 **매일** 한 문제를 제안했지만 매일 콘텐츠를 만드는 운영 비용을 감당할 수 없습니다. 대신 Learning L9(진단 퍼즐)의 엔진 생성 상태를 재사용해 **주 1회** 발행합니다.
- 상황(지표 + 최근 변경) → "무엇을 먼저 확인하겠는가" 선택 + 한 줄 이유 → **답한 뒤에만** 분포 공개(`42% 트레이스 · 27% 배포 diff …`).
- 저장: `wwyd_answers(puzzle_id, user_id, choice, reason)`. 다른 사람의 이유는 작성자가 공개에 동의한 것만.
- **ADR-0040 범위 확장 여부 판단 필요** — 퍼즐은 시나리오 버전이 아니므로, 퍼즐 토론을 열면 "토론은 시나리오 단위"라는 선을 넘습니다. 1차는 토론 없이 분포 + 공개 이유만 보여주고, 토론이 필요하면 그때 결정합니다.

### C13 — 챌린지 이벤트 (후보)

- 기간 한정으로 같은 시나리오를 여럿이 풀고, 종료 후 그 버전의 토론이 "디브리프"로 열리는 형태. 원본의 Weekly Architecture Challenge와 Incident War Game을 합친 것.
- 막는 것: "숨겨진 장애"는 Drill 계획의 Unknown Unknowns 보류 사유(도메인 전용 액션이 원인을 누설)에 그대로 걸리고, 기간 내 비교 지표로 MTTR을 쓰려면 Drill M5(복구 선언)와 관측 O5가 있어야 게이밍에 강한 정의가 됩니다. 1차 기획이 "대응 속도 보드"를 같은 이유로 보류했습니다.
- 재개 조건: M5 · O5 완료 + 토론 활동량 확인.

### C14 — 분야별 평판 (후보)

- 토론·리뷰 댓글에 유형 반응(`도움됨 · 통찰 · 좋은 트레이드오프`)을 달고, 받은 반응을 도메인(시나리오 도메인)별로 합산해 프로필에 표시. 읽기 시점 파생.
- **DrillScore·랭킹과 섞지 않습니다** — ADR-0042가 정한 점수는 훈련 결과만 반영합니다.
- 재개 조건: 반응을 달 만한 글이 충분히 쌓였을 때(표본 없이 평판을 도입하면 초기 소수가 고착).

## 5. 프라이버시 · 안전 · 남용

| 위험 | 대응 |
|---|---|
| 비교 기능으로 남의 설계를 베껴 재도전 | 이미 완료한 사람만 볼 수 있음(ADR-0041). DrillScore는 도메인 최고점이라 베낀 재도전의 이득이 한정적 — 다만 최고점을 올리는 경로는 됨. 재도전율 급증을 §7 지표로 감시 |
| 포크로 남의 대응을 폄하 | 포크 결과는 저장·자동 게시하지 않음(C9) |
| 앵커 댓글 남용 | C7 신고·숨김 재사용, 풀이 비공개 전환 시 함께 숨김 |
| 익명 풀이의 신원 추정 | 비교 화면·홈 카드에서도 익명 설정을 그대로 존중 |
| 랭킹 숨김 사용자 노출 | 홈의 새 카드들도 숨김 사용자 제외(1차 기획 공개 범위 원칙) |

## 6. ADR 후보

1. **C12 퍼즐에 토론을 열 것인가** — 열면 ADR-0040의 "시나리오 단위" 원칙을 넓히는 결정이므로 그때 ADR로 기록합니다.
2. Fork My Run의 "포크는 영속 세션이 아니다"는 Drill M6에서 기록할 ADR을 따릅니다(이 문서에서 별도로 쓰지 않음).
3. 설계 비교를 LLM이 아니라 토폴로지 차이로 하는 것(§3-2)은 LLM 설명을 나중에 얹을 수 있어 되돌리기 쉬우므로 ADR 대상이 아닙니다.

## 7. 성공 지표

| 지표 | 왜 |
|---|---|
| 리포트 → 토론/풀이 진입률 (C7·C11) | 커뮤니티가 Drill 경험의 일부가 됐는가 |
| 풀이 열람 중 "비교하기" 사용률 (C8) | 비교가 핵심 행동인가 |
| 포크 후 원래 시나리오 재도전율 (C9) | "직접 해봐"가 훈련으로 이어지는가 |
| 앵커 댓글 중 리뷰 유형 분포 (C10) | 질문·리스크 중심의 엔지니어링 토론이 생기는가 |
| 동일 시나리오 재도전 비율 | 급증하면 비교 기능이 파밍 도구가 된 것 (1차 기획 지표 유지) |
