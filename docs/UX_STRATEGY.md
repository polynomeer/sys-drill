# UI/UX 고도화 전략

> Phase 1~6과 상용화 가드(이메일/보안/CI 등)는 기능적으로 완결됐지만, 프론트엔드는 "기능이 동작하는 26개 페이지"를 각자 따로 만든 상태에 가깝다 — 공유 컴포넌트 3개(`BridgeProgress`, `PhaseTimer`, `MermaidDiagram`)를 빼면 모든 페이지가 버튼·카드·로딩 문구까지 직접 손으로 짠 Tailwind 문자열이다. 이 문서는 실제로 앱을 띄워서 확인한 현재 상태를 근거로, 어디부터 손대야 "기능은 되는데 완성도가 낮다"는 인상을 벗어날 수 있는지 정리한다.
>
> 대상 사용자는 PRD.md 4.1절의 "2~7년차 백엔드 개발자"다 — 개발자 도구에 익숙하고 밀도 높은 정보를 선호하는 층이므로, 방향은 화려한 컨슈머 앱이 아니라 **Linear/Vercel/GitHub류의 절제된 개발자 도구 미학**(다크 우선, 타이포그래피와 여백으로 위계를 만들고, 색은 정보 전달에만 아껴 쓰는)이다.

## 지금 상태를 직접 확인해서 찾은 것

### 즉시 고쳐야 하는 버그 4가지 (의견이 아니라 사실)

1. **폰트가 의도한 대로 적용되지 않는다.** `globals.css`가 `body { font-family: Arial, Helvetica, sans-serif; }`를 하드코딩해서, `next/font/google`로 정성껏 로드한 Geist Sans/Mono를 덮어쓴다. 실제 대시보드 페이지에서 `getComputedStyle(document.body).fontFamily`를 찍어보면 `"Arial, Helvetica, sans-serif"`가 나온다 — 랜딩 페이지(`app/page.tsx`, `font-sans` 클래스를 직접 붙인 유일한 페이지) 말고는 **전체 앱이 처음부터 지금까지 Arial로 렌더링되고 있었다.**
2. **헤더 내비게이션이 데스크톱에서도 단어 중간에서 줄바꿈되고, 모바일에서는 한 글자씩 세로로 쌓인다.** 대시보드를 1440px 너비에서 열어도 본문 컨테이너가 `max-w-2xl`(672px)로 고정돼 있어 "마켓플레이스·인증·정적 분석·조직·로그아웃" 5개 링크가 242px 폭에 욱여넣어진다. 데스크톱에서는 "마켓/플레이스"처럼 중간에서 끊기고, 375px 모바일 뷰포트에서는 각 링크가 글자 하나당 한 줄씩 세로로 쌓이는 완전히 깨진 레이아웃이 나온다. 공용 내비게이션 컴포넌트가 없고 페이지마다 `flex items-center gap-4`를 반복해서 만든 결과다.
3. **브라우저 탭 제목이 아직도 "Create Next App"이다.** `app/layout.tsx`의 `metadata`가 `create-next-app` 스캐폴드 기본값 그대로다 — 실사용자에게 탭/북마크/공유 링크 미리보기 전부 이 제목으로 노출된다.
4. **파비콘도 커스터마이즈된 적이 없어 보인다**(`favicon.ico`가 Next.js 기본 아이콘 크기·구성과 일치, 3번과 함께 브랜딩 자체가 한 번도 손댄 적 없는 상태임을 시사).

이 4개는 "전략"이 필요 없다 — 다음에 프론트엔드를 만질 때 바로 고치면 된다.

### 구조적으로 반복되는 것 (숫자로 확인)

- `"불러오는 중..."` 로딩 문구가 19개 파일에서 각각 하드코딩됨(공유 `LoadingState` 컴포넌트 없음).
- `"rounded bg-foreground px-..."` 형태의 버튼 스타일이 28곳에서 반복(공유 `Button` 컴포넌트 없음).
- `Card`/`Badge`/`Input`/`EmptyState` 같은 원자적 컴포넌트가 전무 — 26개 페이지, 3,918줄의 페이지 코드가 전부 인라인 Tailwind다.
- 색은 사실상 흑백+zinc 회색조뿐이다. 위험도(HIGH/MEDIUM), 난이도(EASY/MEDIUM), 상태(완료/미완료/진행중) 같은 의미 있는 값들이 거의 전부 **일반 텍스트**로만 표현된다 — 유일한 예외는 이번 세션에서 만든 Architecture Linter 다이어그램의 빨강/노랑 노드 색칠뿐이다.

## 페이지별로 실제로 본 것

- **온보딩/로그인**: 순수 검정 배경에 좁은 폼 하나가 덩그러니 떠 있다. 로고·아이콘 없이 텍스트 "SysDrill"이 브랜드의 전부. 기능은 멀쩡하지만 "제품"이라기보다 관리자 도구 느낌.
- **대시보드**(허브 페이지): 위 내비게이션 버그 외에도, Bridge Mode 카드·일반 시나리오 카드·"최근 진행" 카드가 전부 같은 회색 테두리 박스로 동일한 시각적 무게를 가진다. PRD.md가 "핵심 차별점"이라 부르는 Bridge Mode가 다른 시나리오 7개와 똑같은 카드로 묻혀 있다.
- **System Design Workspace**(제품의 핵심 루프, 사용자가 가장 오래 머무는 화면): 문제 설명·답안 가이드·답안 입력·다이어그램 미리보기가 전부 같은 회색 박스 4개로 나열된다. 정작 가장 중요한 "문제" 패널이 아래 힌트 목록과 시각적으로 구분되지 않는다. 답안 textarea는 약 150px 높이로 좁고, 자동 확장·전체화면·글자 수 표시가 없다. **PRD.md가 핵심으로 꼽는 "초기 설계 → 꼬리설계 → 장애 대응" 3단계 진행 상태를 보여주는 표시가 이 화면 어디에도 없다** — `BridgeProgress`는 Bridge Mode 전용이라 이 3단계에는 안 쓰인다. 이번 세션에 만든 Mermaid 다이어그램 미리보기도 접혀 있는 듯한 작은 박스에 묻혀 있다.
- **마켓플레이스**: 시나리오 목록과 "새 시나리오 등록" 폼이 같은 시각적 무게의 박스 안에 나란히 있다. 목록의 각 항목은 제목·난이도·제작자가 한 줄에 구분 없이 붙어 있어 스캔하기 어렵다.
- **인증(Certification)**: "SysDrill Certified Incident Responder"라는, 원래 성취감을 줘야 할 배지 개념의 기능인데 실제로는 작은 체크박스 7개와 "미완료" 텍스트 7번 반복뿐이다. 진행률 바도, 배지 이미지도, 완료 시 축하 화면도 없다. 공개 검증 링크도 스타일 없는 raw URL 텍스트로만 노출(복사 버튼조차 없음).

## 전략: 4단계로 나눠서 간다

레버리지(적은 노력으로 전체 앱에 퍼지는 효과) 순서다 — 뒤 단계로 갈수록 개별 화면에 공을 들이는 작업이라 먼저 기초를 다지지 않으면 각 화면을 두 번 손대게 된다.

### Phase A — 기초 공사 (버그 수정 + 디자인 시스템 뼈대)

가장 적은 코드로 전체 앱의 인상을 가장 크게 바꾸는 단계.

1. 위 4개 버그 수정(폰트, 내비게이션 wrap, 탭 제목, 파비콘).
2. `frontend/src/components/ui/`에 최소 원자 컴포넌트 5~6개 신설: `Button`(primary/secondary/danger variant), `Card`, `Badge`(색상 variant: neutral/success/warning/danger — 난이도·상태·위험도에 공통 사용), `EmptyState`, `Spinner`/`LoadingState`, `Input`. 새로 만들 필요 없이 **이미 28번·19번 반복된 패턴을 그대로 컴포넌트로 뽑아내는 것**이라 디자인 결정이 거의 필요 없다.
3. 액센트 컬러 하나를 `globals.css`의 CSS 변수로 도입(`--accent` 등) — 지금은 순수 흑백이라 "핵심 액션"과 "보조 액션"을 색으로 구분할 방법이 없다. 개발자 도구 톤에 맞는 절제된 색(예: indigo/blue 계열 하나) 하나면 충분하다.
4. `app/layout.tsx`에 실제 앱 셸(고정 헤더: 로고, 내비게이션, 사용자 메뉴/로그아웃, 모바일 햄버거 메뉴)을 만들어 26개 페이지가 각자 만들던 "뒤로가기"/내비게이션 링크를 걷어낸다. `AuthWebConfig`가 인증 필요 경로를 이미 명확히 구분해두었으니, 로그인 여부에 따라 헤더 내용을 바꾸는 것도 자연스럽다.

### Phase B — 레이아웃과 반응형

1. 고정 `max-w-2xl`/`max-w-3xl`을 화면 크기에 맞게 스케일하는 레이아웃으로 교체(예: 목록형 페이지는 `max-w-5xl`, 텍스트 중심 폼은 지금처럼 좁게 유지하되 컨테이너 자체는 뷰포트에 반응하게). 모든 페이지를 한 번에 바꿀 필요는 없다 — Phase A의 앱 셸과 자주 쓰는 페이지(대시보드, Design Workspace, 마켓플레이스, 조직)부터.
2. 실제 모바일 QA 패스 — 지금까지 단 한 번도 375px 뷰포트에서 검증된 적이 없다는 게 이번에 확인한 사실이다. 헤더 붕괴부터 고치고 나면, 카드 목록이 좁은 화면에서 제대로 쌓이는지, 터치 타깃이 충분히 큰지 화면별로 훑는다.
3. Badge 컴포넌트를 실제로 걸기 시작: 난이도(EASY/MEDIUM/HARD), 시나리오 상태(진행중/완료/실패), 인증 상태(완료/미완료), 마켓플레이스 시나리오 도메인 라벨에 색을 부여해 스캔 속도를 올린다.

### Phase C — 핵심 루프 화면 리디자인

가장 오래 머무는 화면 3곳에 집중 투자.

1. **System Design Workspace**: 문제 패널을 액센트 컬러 테두리·더 큰 타이포그래피로 명확히 승격, 답안 textarea를 더 크게(또는 전체화면 포커스 모드) + 자동 확장, 3단계(초기 설계→꼬리설계→장애 대응) 진행 스테퍼를 상단에 상시 노출(`BridgeProgress`와 같은 패턴을 일반 시나리오용으로 확장), Mermaid 다이어그램 미리보기를 접히지 않는 사이드 패널이나 탭으로 승격.
2. **리포트/피드백 화면**: 100점 만점 점수와 루브릭 항목을 막대/방사형 차트로 시각화(이미 `mermaid`가 들어와 있으니 `pie`/`bar` 차트류를 재사용하거나, 간단한 CSS 바 차트로도 충분), 타임라인을 불릿 목록이 아니라 실제 타임라인 UI로.
3. **인증 페이지**: 진행률 바("7개 도메인 중 3개 완료") + 완료된 도메인마다 실제 배지 비주얼, 전체 인증 완료 시 축하 상태, 공개 검증 링크에 복사 버튼.

### Phase D — 디테일과 동기부여

1. 로딩 스켈레톤(최종 레이아웃 형태를 흉내 낸) 도입 — 모든 "불러오는 중..." 텍스트를 대체.
2. 빈 상태(empty state)에 안내 문구+다음 행동 유도 버튼을 갖춘 일관된 컴포넌트 적용("아직 등록된 시나리오가 없습니다" 같은 문장이 여러 곳에 흩어져 있음).
3. 토스트/스낵바 알림 도입(초대 발송됨, 저장됨 등 — 지금은 전부 인라인 텍스트나 리다이렉트로만 피드백).
4. Build 모드의 실제 코드 입력이 여전히 plain `<textarea>`다(ARCHITECTURE.md가 진작 "Monaco Editor 검토"라고 남겨둔 부분) — 최소한 모노스페이스 폰트 강제 + 탭 들여쓰기 정도는 지금 바로 가능하고, Monaco/CodeMirror 도입은 별도 스코핑이 필요한 더 큰 작업이라 이 문서에서는 방향만 남긴다.

## 우선순위 요약

지금 당장 시작한다면: **Phase A의 4개 버그부터 고치고, 그 자리에서 바로 앱 셸(헤더/내비게이션)과 버튼/카드/배지 컴포넌트를 만드는 것**이 압도적으로 ROI가 높다 — 이 하나의 작업이 26개 페이지 전부의 일관성과 브랜드 인상을 동시에 끌어올리고, 이후 Phase B~D의 모든 작업이 이 컴포넌트들 위에서 더 빨리 진행된다.

## Phase A 완료 (2026-09-09)

버그 4개 전부 수정, `frontend/src/components/ui/`에 `Button`/`Card`/`Badge`/`Alert`/`Input`(+`Textarea`)/`LoadingState`/`EmptyState` 신설, `AppHeader`(고정 헤더 + 모바일 햄버거 메뉴) 도입, 26개 페이지 전부 마이그레이션 완료. `npx tsc --noEmit`/`npm run lint`(0 errors)/`npm run build` 모두 통과, 데스크톱(1440px)·모바일(375px) 실브라우저 검증 및 조직 생성/멤버 초대 핵심 플로우 재확인 완료.

작업 중 계획에 없던 추가 수정 2건:
- `src/app/favicon.ico`(create-next-app 기본 파비콘)가 남아 있어 `icon.svg`를 만들어도 실제로는 여전히 기본 아이콘이 브라우저 탭에 노출되고 있었다 — Next.js는 같은 디렉터리에서 `favicon.ico`를 `icon.svg`보다 우선한다. 파일을 삭제해 `icon.svg`가 실제로 적용되도록 함.
- `organizations/[orgId]/page.tsx`의 초대 성공 메시지가 "이메일은 자동 발송되지 않습니다"였는데, 상용화 라운드에서 실제 이메일 발송을 이미 붙였기 때문에 이 카피가 사실과 어긋나 있었다 — "초대 이메일을 발송했습니다"로 정정.

Phase B(반응형 레이아웃), Phase C(핵심 루프 화면 리디자인), Phase D(로딩 스켈레톤/토스트/Monaco)는 위 계획대로 미착수 상태로 남아 있다.

## 별도 트랙 — 외부 디자인 기획서 기반 전면 리뉴얼 (2026-09-09~)

사용자가 외부에서 작성된 `SysDrill_UIUX_Design_Plan.docx`(다크 네이비 콘솔 톤, Home/Drills/Learning/Community IA, "Drill" 용어 체계)를 기준으로 화면 기획을 다시 하고 UI/UX를 리뉴얼해달라고 요청했다. 이 문서의 방향은 Phase A(라이트 테마, 기존 IA 유지)와 다르며, Phase A 위에 이어가는 것이 아니라 **Phase A의 디자인 토큰과 컴포넌트를 다크 네이비 팔레트로 교체하는 별도 리브랜드**다. 진행 상황은 [PLAN.md](../PLAN.md)의 "UI/UX 리뉴얼" 절을 참고 — Phase A~D 번호 체계와는 독립적으로 Round 1/2/3으로 진행한다.
