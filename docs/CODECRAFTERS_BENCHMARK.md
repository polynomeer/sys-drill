# CodeCrafters 벤치마킹 — UI/UX 전체 개선안

> [app.codecrafters.io](https://app.codecrafters.io/)는 "시니어 개발자가 Redis·Git·Kafka를 직접 만들어보는" 챌린지 플랫폼이다. 타깃(경력 개발자), 형식(작게 쪼갠 단계 + 자동 검증), 톤(다크 개발자 도구)이 SysDrill과 가장 가까운 레퍼런스라, 이 문서는 그들의 화면을 실제로 둘러보고 **"무엇을 가져오고, 무엇을 가져오지 않을지"**를 SysDrill의 현재 화면과 1:1로 대조해 정리한다.
>
> 선행 문서와의 관계: [UX_STRATEGY.md](UX_STRATEGY.md)(Phase A + 다크 네이비 리뉴얼 Round 1~4)가 **디자인 시스템과 개별 화면의 완성도**를 다뤘다면, 이 문서는 그 위에서 **학습 루프의 구조**(카탈로그 → 상세 → 단계별 진행 → 피드백 → 다음 단계 → 공유)를 다룬다. Learning/Community 세부 설계는 [LEARNING_COMMUNITY_PLAN.md](LEARNING_COMMUNITY_PLAN.md)에 이미 있으므로 여기서는 CodeCrafters와의 대응 관계만 짚고 중복 설계하지 않는다.

## 0. 조사 방법과 한계

- **직접 관찰(2026-09-30, 비로그인)**: 카탈로그(`/catalog`), 챌린지 개요(`/courses/redis/overview`), 언어 트랙(`/tracks/go`), 공개 프로필(`/users/<id>`), 개념 라이브러리(`/concepts`, `/concepts/redis-protocol`), 문서(`docs.codecrafters.io` — "How do challenges work?", CLI 사용법).
- **관찰하지 못한 것**: 로그인 후의 스테이지 작업 화면(스테이지 클릭 시 GitHub 로그인으로 리다이렉트됨). 이 화면에 대한 서술은 공식 문서 내용에 근거하며, 본문에 **(문서 기준)**으로 표시했다.
- **SysDrill 현재 상태**: `frontend/src/` 전체를 훑은 인벤토리 기준(2026-09-30, `main`).

## 1. CodeCrafters에서 관찰한 것

### 1.1 비주얼 언어

- **다크 네이비 + 채도 낮은 틸(teal) 단일 액센트.** 주요 CTA("Start Building")는 틸 배경 버튼 하나뿐이고, 나머지는 테두리만 있는 보조 버튼 또는 텍스트 링크다. 색을 "누를 곳"에만 쓴다.
- **두꺼운 기하학적 산세리프 헤드라인**("Build your own Redis", "Master Go.")과 작은 회색 서브카피의 강한 대비. 페이지마다 헤드라인이 곧 가치 제안이다.
- **챌린지마다 고유 아이콘**(Redis 벽돌, Git 로고, 터미널 프롬프트 등)이 카드 우상단에 붙어, 텍스트를 읽기 전에 식별된다.
- **난이도 표기 = 대문자 라벨 + 3칸 신호 막대**(VERY EASY / EASY / MEDIUM / HARD). 색은 하나(틸)로 통일하고 막대 개수로 강도를 표현한다 — 빨강/노랑 같은 경고색을 난이도에 쓰지 않는다.
- **잠긴 콘텐츠는 불투명도를 낮춘 카드 + 자물쇠 아이콘**으로 표현한다. 숨기지 않고 "여기에 이만큼 더 있다"를 보여준다.
- 이모지 없음. 아이콘은 전부 단색 라인 아이콘이다.

### 1.2 정보 구조 (IA)

| 화면 | 구성 |
|---|---|
| 카탈로그 | 상단 "New here? **Start here**" 안내 배너 → 2열 챌린지 카드(제목·한 줄 설명·스테이지 수·아이콘) → 하단 "Language Tracks" 그리드(언어별 스테이지 수, Popular 배지) |
| 챌린지 개요 | 좌: 헤드라인 + 지원 언어 아이콘 줄 + 단일 CTA → 소개 문단 → FAQ 아코디언 4개("무엇을 만드나/배우나/왜/선수지식") → **전체 스테이지 목록**(확장 모듈별 그룹, 각 행에 난이도) · 우: **Recent Attempts**(최근 도전자 아바타 + 개인별 진행 막대 "92 / 124") + Invite a friend · 하단: 추천사 |
| 언어 트랙 | "Master Go." + 학습자 수·연습 수 → 그 언어로 풀 수 있는 챌린지들(스테이지 미리보기) · 우측 **언어별 리더보드** |
| 공개 프로필 | 아바타·GitHub 링크·사용 언어 아이콘 → 완료 챌린지 카드 그리드("using C++", completed) → **월별 활동 타임라인**("Completed the Build your own Redis challenge using C") |
| 개념(Concepts) | 카드 그리드(제목·한 줄 설명·읽기 시간) → 상세는 **한 문단씩 드러나는 점진적 공개**, "Continue" 버튼 + `Enter ↵` 단축키, 저자 표시, 우측에 읽기 시간 |

### 1.3 학습 루프 (문서 기준)

1. 언어 선택 → 전용 git 저장소 생성 → 테스트 커밋 push로 환경 확인 → 자동으로 1단계 진입.
2. **1단계는 의도적으로 사소하다**("Bind to a port", VERY EASY — 주석 해제 후 push면 통과). 첫 성공 경험을 몇 분 안에 준다.
3. 각 단계는 TDD처럼 "실패하는 테스트 → 통과"로 진행되고, 결과는 `git push` 출력 또는 CLI(`codecrafters test`)로 **스트리밍 로그**가 흘러나온다. 로그는 `[compile]`, `[stage-1]`, `[your_program]` 접두어로 출처를 구분한다.
4. 실패 시 로그 끝에 다음 행동("try setting `debug: true`…")과 지시문 링크를 붙인다.
5. 통과하면 웹 UI가 자동으로 다음 단계 지시문을 보여준다. 지시문은 **선택한 언어에 맞춰** 작성된다.
6. `--previous` 플래그로 이전 단계 회귀 테스트까지 돌릴 수 있다.

### 1.4 동기 부여 장치

- 스테이지 수를 숫자로 노출("124 stages") — 규모 자체가 성취 목표가 된다.
- Recent Attempts의 개인별 진행 막대 — "다른 사람도 지금 하고 있다"는 사회적 증거.
- 언어별 리더보드, 공개 프로필 타임라인 — 완료가 공유 가능한 기록으로 남는다.
- 무료 챌린지 하나(Shell)를 전면에 둬 "일단 시작"의 장벽을 없앤다.

## 3. 개선안

영역별로 "CodeCrafters에서 가져올 것 → SysDrill에 맞게 바꾼 형태 → 구현 메모" 순서로 적는다.

### 3.1 Drill 개요(Overview) 페이지 신설 — G1, G2

**가장 먼저 할 일.** 지금은 목록에서 바로 세션이 생기므로, 사용자는 "이게 무슨 문제인지"를 세션을 만든 뒤에야 안다.

- 라우트: `/drills/[scenarioId]` (Build는 `/drills/build/[challengeId]`).
- 구성(CodeCrafters 개요 페이지 레이아웃 그대로):
  - **헤더**: Drill 제목(큰 헤드라인) + 한 줄 요약 + 타입 배지(Design/Build/Incident) + 도메인 아이콘 + 단일 CTA "시작하기" (진행 중 세션이 있으면 "이어하기").
  - **FAQ 아코디언 4개**: "무엇을 설계하나요 / 무엇을 배우나요 / 실무에서 왜 중요한가요 / 선수 지식" — 기존 시나리오 필드와 선행 추천(`dashboard`의 "선행 추천")을 여기로 옮긴다.
  - **스테이지 로드맵**: 요구사항 분석 → 초기 설계 → 확장 시나리오(꼬리설계) → 장애 대응(Wargame) → 리포트. 각 행에 예상 소요 시간과 평가 항목 수. Bridge Mode 시나리오라면 맨 앞에 Build 스테이지들을 붙인다.
  - **우측 레일 — 최근 도전자**: 최근 이 Drill을 시도한 사용자(닉네임 + 진행 막대 "3 / 5 단계"). 공개 동의한 사용자만(§4 프라이버시). 아래에 "이 Drill의 평균 점수 / 완료자 수" — LEARNING_COMMUNITY_PLAN C1 벤치마크 데이터를 그대로 재사용.
  - **하단**: 완료 후 열리는 것(풀이 공유 — ADR-0041, 토론 스레드 — ADR-0040)을 잠금 아이콘과 함께 미리 보여준다.
- 목록의 "시작" 버튼은 전부 이 페이지로 링크를 바꾼다. 세션 생성은 개요 페이지의 CTA에서만.

### 3.2 스테이지 기반 진행 모델을 UI 전면에 — G2, G3

SysDrill은 이미 단계 모델(Design 세션 phase, Build 6개 테스트)을 갖고 있지만 **화면이 그것을 보여주지 않는다**. 데이터 모델 변경 없이 표현만 바꿔도 효과가 크다.

- **공용 `StageList` 컴포넌트** — CodeCrafters 스테이지 행 형태: 상태 점(완료 ●/현재 ◐/잠김 ○) + 단계 아이콘 + 제목 + 난이도 라벨·신호 막대. 개요 페이지, 작업 화면 좌측 패널, 리포트에서 같은 컴포넌트를 쓴다. 지금의 `StepNav`(완료 단계를 취소선으로 표시)와 `BridgeProgress`를 이것으로 흡수한다.
- **Build 챌린지를 단계별 잠금 해제로**: rate-limiter의 6개 테스트를 6개 스테이지로 노출한다.
  - 1단계는 CodeCrafters처럼 **거의 공짜로 통과**하게 설계("고정 한도로 첫 요청 허용" 수준) — 첫 성공까지 5분 이내.
  - 각 스테이지에 전용 지시문(목표 · 입력/출력 예 · 테스트가 확인하는 것)을 두고, 통과하면 다음 지시문이 열린다.
  - 채점은 지금처럼 전체 테스트를 돌리되, UI는 "현재 스테이지까지"를 기준으로 합격 여부를 보여주고 이후 스테이지 결과는 접어 둔다(`--previous`처럼 이전 단계 회귀는 항상 함께 표시).
  - 이 변경은 채점 백엔드(`challenges/rate-limiter` 테스트 러너)에 "스테이지 번호별 결과"가 이미 있으므로 프론트 위주 작업이다. 스테이지별 지시문 콘텐츠는 ADR-0002(콘텐츠는 마이그레이션으로)를 따른다.

### 3.3 작업 화면 레이아웃 — G4, G5

- **2분할 레이아웃**(데스크톱 ≥1024px): 좌측 380px 고정 패널 = `StageList` + 현재 스테이지 지시문(탭: 지시문 / 힌트 / 개념), 우측 = 작업 영역(Build: 코드 에디터, Design: 텍스트 답안 ↔ 캔버스 탭, Incident: 기존 `WargameLive`). 모바일은 탭 전환으로 접는다.
- **하단 테스트 로그 패널**(Build): CodeCrafters 로그 형식을 차용해 출처 접두어를 색으로 구분한다.
  ```
  [compile]   Python 3.12 — 구문 검사 통과
  [stage-2]   동일 키 11번째 요청 → 429 기대
  [your_code] print() 출력이 여기 표시됩니다
  [stage-2]   ✗ 200을 받았습니다. 윈도우 경계에서 카운터가 초기화되는지 확인하세요
  ```
  실패 마지막 줄에는 항상 **다음 행동 한 문장 + 지시문 앵커 링크**를 붙인다. 폴링 결과를 한 번에 붙이는 방식이라도, 줄 단위로 순차 렌더링하면 체감이 스트리밍에 가깝다.
- **대기 상태 카드**: "채점 중(PENDING)" 같은 raw enum 대신 CodeCrafters의 "Listening for a git push…" 패턴 — 무엇을 기다리는지 + 평균 소요 시간 + 진행 애니메이션.
- **CLI/git 경로 노출**: 스텁 주석에만 있는 `submit.sh` 경로를 "로컬에서 풀기" 탭으로 문서화한다. 브라우저 에디터가 기본, 로컬 제출은 선택 — 경력 개발자에게 자기 에디터를 쓸 수 있다는 건 CodeCrafters가 증명한 강한 매력이다.

### 3.4 첫 경험 — G6

- **`/` 랜딩 페이지**: 헬스체크 JSON을 제거하고(헬스체크는 `/actuator` 또는 관리자 화면으로), CodeCrafters 개요 페이지 톤으로 다시 쓴다 — 헤드라인 "Train. Break. Fix. Repeat." + 3모드 설명 + README 워게임 데모 GIF + "무료로 첫 Drill 시작" CTA. 이미 있는 스크린샷·GIF 자산(`docs/images/`)을 재사용한다.
- **"처음이세요? 여기서 시작" 배너**: Home/Drills 최상단에 닫을 수 있는 안내 배너 → 3분짜리 "SysDrill은 어떻게 동작하나요" 개념 문서(§3.6 형식)로 연결.
- **추천 첫 Drill 하나를 고정**: CodeCrafters가 Shell을 "FREE"로 전면에 두듯, 가장 짧고 성공 확률이 높은 Drill 하나를 "첫 Drill" 배지로 고정한다. 온보딩 직후 이 Drill의 개요 페이지로 보낸다.
- **온보딩에 2문항 추가**: 주 언어(Python/TypeScript — Build 기본 언어로 저장), 목표(면접 준비 / 실무 역량 / 팀 온보딩). 목표는 Home 추천 로직의 가중치로 쓴다. 자유 텍스트 "주 스택" 필드는 선택지로 바꾼다.

### 3.5 카탈로그(Drills) 재구성 — G1, G10

- 목록 행 → **2열 카드 그리드**: 제목 · 한 줄 설명 · 도메인 아이콘 · "5 단계 · 약 40분" · 난이도(신호 막대) · 내 진행 막대(진행 중일 때만).
- System Design 탭과 Incident 탭이 같은 목록을 보여주는 현재 상태(`marketplace/page.tsx:218-219`)는 탭을 **"Design → Incident 통합 Drill" 하나**로 합치고, 각 카드에 두 모드를 모두 포함한다고 표시하는 편이 정직하다.
- 카탈로그 하단에 **도메인 트랙 섹션**(§3.7)을 CodeCrafters의 "Language Tracks" 위치에 둔다.
- 마켓플레이스 "시나리오 등록" 폼은 목록 페이지에서 분리해 `/drills/new`로 옮긴다(목록 밀도 완화).

### 3.6 Learning — 점진적 공개형 개념 문서 — G9

LEARNING_COMMUNITY_PLAN §5.2(L1 개념 라이브러리, ADR-0039로 DB 이관 결정)의 **렌더링 방식**으로 CodeCrafters 형식을 채택한다.

- 개념 상세는 한 번에 전부 보여주지 않고 **블록 단위 점진적 공개**: 문단 → "계속 (Enter ↵)" → 다음 문단. 중간에 1문항 퀴즈 블록을 끼워 넣을 수 있게 블록 타입을 `paragraph | code | diagram | quiz`로 둔다.
- 카드에 **읽기 시간**("3분")과 저자 표시.
- 개념 끝에 "이 개념을 쓰는 Drill" 카드(L3 — 개념에서 훈련으로 진입)를 붙이고, 반대로 작업 화면 좌측 패널의 "개념" 탭에서 관련 개념을 바로 연다 — CodeCrafters가 스테이지 지시문 안에서 개념을 링크하는 방식.

### 3.7 도메인 트랙 — G7

CodeCrafters의 축이 "언어"라면 SysDrill의 축은 **"도메인"**(결제·쿠폰·알림·오토스케일링 등)이다.

- `/tracks/[domain]`: 헤드라인 "결제 시스템 마스터" + 학습자 수 · Drill 수 → 해당 도메인의 Build/Design/Incident Drill을 순서대로(선행 관계 반영) → 우측 **도메인별 랭킹**(ADR-0042 Drill Score의 도메인 필터 뷰).
- 인증(Certification)을 트랙에 연결: 트랙의 모든 Drill 통과 = 해당 도메인 인증 배지. 지금 링크되지 않은 `/certifications`가 자연스럽게 발견된다.

### 3.8 사회적 증거와 공유 — G8

신규 설계는 LEARNING_COMMUNITY_PLAN C1/C4/C6에 이미 있으므로, 여기서는 **CodeCrafters가 이를 어디에 배치하는지**만 반영한다.

- **개요 페이지 우측 레일** = 최근 도전자 + 진행 막대 (§3.1). 랭킹 보드를 별도 페이지에 두는 것보다 "지금 이 Drill을 고르려는 순간"에 보이는 쪽이 전환에 기여한다.
- **공개 프로필 활동 타임라인**: "2026년 9월 — 쿠폰 발급 Drill 완료 (82점)". 월별 그룹, 완료 이벤트만. 기존 `/profile`의 레이더 차트·추이는 본인 전용으로 두고, 공개 프로필은 CodeCrafters처럼 완료 카드 + 타임라인으로 단순하게.
- **완료 순간 연출**: 스테이지 통과 시 체크 애니메이션, Drill 완료 시 요약 카드(점수 · 소요 시간 · 트랙 진행) + "프로필에 공유" / 링크 복사. 인증의 공개 검증 링크와 같은 OG 이미지 경로를 재사용.
- **Invite a friend**: 개요 페이지 레일 하단에 초대 링크. 조직 초대(ADR-0022/0023)와는 별개의 가벼운 공유 링크다.

### 3.9 비주얼 시스템 다듬기 — G10, G11

리뉴얼 Round 1의 다크 네이비 토큰은 유지하고, 아래만 보강한다.

- **이모지 → 라인 아이콘**: `lucide-react` 도입(트리 셰이킹, 단색 `currentColor`). 헤더 🔔/☰, `WargameLive` 액션 카테고리, 커리큘럼 ✅/⬜️를 교체.
- **도메인 아이콘 세트**: 도메인마다 단색 아이콘 하나(결제=카드, 쿠폰=티켓, 알림=벨, 오토스케일링=서버 스택…). 카드·트랙·배지에 공통 사용.
- **`DifficultyBadge`**: 대문자 라벨 + 3칸 신호 막대, 색은 액센트 한 가지. 지금 난이도에 쓰는 success/warning/danger 색은 **상태**(통과/경고/실패) 전용으로 되돌린다 — 색 의미가 두 가지로 겹치지 않게.
- **액센트 사용 규칙**: 화면당 primary 버튼 1개. CodeCrafters처럼 "누를 곳 하나"를 색으로 가리킨다.
- **잠김 상태 스타일**: 불투명도 40% + 자물쇠 아이콘 + 툴팁("이전 단계를 통과하면 열립니다"). §3.2 스테이지 잠금, §3.1 완료 후 콘텐츠에 공통.
- **키보드 퍼스트**: 개념 문서 Enter 진행, 작업 화면 `⌘↵` 제출, `j/k` 스테이지 이동. 단축키는 버튼 아래 작은 힌트로 노출(CodeCrafters "Enter ↵" 표기).
- **발견 가능성**: 헤더 아바타 메뉴에 "인증", "조직", "아키텍처 분석"을 추가하고, 도메인 트랙에서 인증으로, 프로필에서 조직으로 연결.
- **공용 컴포넌트 추가**: `Tabs`, `Tooltip`, `ProgressBar`, `Skeleton`, `Toast`, `Accordion`, `Avatar` — 지금 페이지마다 손으로 만든 진행 막대·탭을 흡수.

## 4. 가져오지 않을 것

| CodeCrafters 요소 | 가져오지 않는 이유 |
|---|---|
| git push가 유일한 제출 경로 | SysDrill의 Design/Incident는 텍스트·캔버스·실시간 액션이라 브라우저가 본질이다. Build만 로컬 경로를 **선택지**로 둔다(§3.3). |
| 124단계 같은 거대한 챌린지 | 시스템 설계 Drill은 한 세션 30~60분이 적정. 규모는 "단계 수"가 아니라 "트랙 안의 Drill 수"로 표현한다. |
| 멤버십 잠금 배너가 개요 상단을 차지하는 구성 | 과금 모델(COMMERCIALIZATION.md)이 확정되기 전까지 잠금 UI는 "완료 후 열리는 콘텐츠"에만 쓴다. |
| 모든 도전자의 진행 상황 공개 | CodeCrafters는 GitHub 공개 프로필이 전제지만 SysDrill은 이메일 가입이다. 최근 도전자·타임라인은 **공개 프로필을 켠 사용자만** 노출한다(LEARNING_COMMUNITY_PLAN §7). |
| 영어 전용 카피 | 타깃이 국내 개발자. 헤드라인에 영어 슬로건은 써도 지시문·피드백은 한국어 유지. |

## 6. 성공 지표

| 지표 | 측정 | 기대 방향 |

| 첫 세션 완료율 (가입 후 7일 내) | 가입자 중 1개 이상 Drill 리포트 도달 | ↑ (첫 Drill 고정·1단계 사소화 효과) |

## 7. 열어둔 질문

- Build 스테이지 지시문을 언어별로 따로 쓸 것인가(CodeCrafters 방식), 공통 지시문 + 언어별 코드 스니펫으로 갈 것인가. 현재 언어가 2개(Python/TypeScript)라 후자가 유지비가 낮다.
- 개요 페이지를 비로그인 사용자에게 공개할 것인가. CodeCrafters는 개요·스테이지 목록을 공개해 검색 유입을 얻는다 — 공개하면 랜딩 페이지 역할까지 겸한다.
- "최근 도전자" 레일에 노출할 최소 인원. 초기엔 사용자 수가 적어 비어 보일 수 있으므로, N명 미만이면 레일 대신 "평균 점수·완료자 수"만 보여줄지.
