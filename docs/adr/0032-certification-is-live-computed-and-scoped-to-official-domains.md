# "SysDrill Certified Incident Responder" is a live-computed judgement, never issued or persisted, and only counts official Flyway-seeded domains

`CertificationService.status()` recomputes eligibility from `Session`/`Submission`/`Evaluation` on every `GET /certifications/{userId}` call — there is no `certifications` table, no issuance event, no expiry. This mirrors [0011](0011-derived-values-are-never-persisted.md)'s "interpreted values are computed at read time" and reuses the same "batch-load a user's Session history, join at read time" shape the team dashboard (PLAN.md step 33) and [the onboarding curriculum](0030-onboarding-curriculum-is-advisory-full-replace-and-counts-retroactive-completion.md) (PLAN.md step 39) already established, rather than adding new state. The name invites a different mental model — a real certification is usually a point-in-time event you keep even if your skills later lapse — but nothing in this codebase issues durable credentials yet (no payment, no admin-review workflow, no expiry policy), and building that machinery before anyone has asked to rely on the credential would be speculative. If a real issuance model is needed later (e.g., a resume-shareable certificate that shouldn't flicker off), it's a separate table and an explicit issuance action layered on top of this same eligibility calculation — this decision doesn't block that.

Only scenarios with `organizationId == null && creatorUserId == null` — the original Flyway-seeded content ([0002](0002-content-via-migrations-not-admin-crud.md)) — count toward certification, deliberately excluding both organization-scoped custom scenarios ([0024](0024-custom-scenarios-coexist-with-migration-content-and-scope-cut-to-design-only.md)) and Phase 5's marketplace scenarios ([0031](0031-marketplace-scenarios-join-the-public-pool-with-no-payment-in-v1.md)). Marketplace scenarios in particular are publishable by anyone with zero review (0031's own choice), so counting them toward a credential named "Certified" would let a user manufacture their own easy-to-pass domain and certify through it — the official domain set is the only content this platform has actually curated. The passing score (`sysdrill.certification.passing-score`, default 70) is a config value rather than a hardcoded constant for the same reason state is never persisted here: since eligibility is recomputed live, moving the bar later needs no migration and no backfill, only a config change.
