# The "autoscaling" domain stays rule-based — no real Kubernetes cluster, unlike coupon/notification's real-infra pilots

PLAN.md step 29 was originally scoped as "고급 Kubernetes 시나리오" following ROADMAP.md's Phase 3 sketch ("실제 컨테이너 기반 의존성 도입... Kubernetes"), which reads as a natural next real-infra pilot alongside coupon (step 21, Postgres/Redis) and notification (step 27, Kafka). We didn't build one. Asked directly, the user chose a rule-based new domain over standing up a real cluster (kind/minikube) or skipping the step entirely.

The two prior real-infra pilots both added an opt-in real-infra `SimulationEngine` to an *already-existing* rule-based domain — coupon and notification were already scenarios with a rubric, risk concepts, and rule-based mechanics; the real-infra path was purely additive. Kubernetes has no such existing domain to attach to, so this step is a genuinely different kind of decision: not "should this existing domain also get a real backend," but "should we stand up a wholly new, heavier infrastructure dependency (a real cluster, image builds, pod scheduling) on a solo dev laptop that already runs Postgres/Redis/Kafka/Toxiproxy/Jaeger for the other pilots." That crosses the threshold docs/ARCHITECTURE.md §1 원칙 7 draws by default ("실제 인프라를 매 세션 띄우지 않는다") — the two existing pilots already deliberately revisited that principle once each with a specific cost/benefit case; a third revisit for the heaviest infrastructure of the three needed the same explicit case, which is what running it past the user gave.

Instead, "autoscaling" ships as a seventh purely rule-based domain (a new scenario, `RuleBasedSimulationEngine.Autoscaling`, `RuleEvaluator`'s `autoscalingConcepts`) — same MVP-default mechanism every domain used before Phase 3's real-infra experiments started. Its mechanic is still genuinely distinct per ADR-0012: effective pod capacity is reduced by two *independent, multiplicative* penalties (OOM crash-loop from untuned resource limits, and an unsafe rolling deployment), which is why scaling out alone barely helps — a lesson none of the other six domains teach, since none of them model horizontal capacity being undermined by per-unit reliability. If a future step wants a real-cluster pilot for this domain, `EngineMode.REAL_INFRA` and the domain→engine map (ADR-0018) already have room for a `RealInfraAutoscalingEngine` without touching this rule-based path.
