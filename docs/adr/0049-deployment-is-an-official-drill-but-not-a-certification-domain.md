# Deploy 도메인은 공식 Drill이지만 인증 도메인 목록에는 들어가지 않는다

8번째 공식 도메인 `deployment`(카나리 배포 결함 — [DRILLS_EXPANSION_PLAN.md](../DRILLS_EXPANSION_PLAN.md) M9)를 추가한다. 인증([ADR-0032](0032-certification-is-live-computed-and-scoped-to-official-domains.md))은 지금까지 "공식 시나리오의 모든 도메인을 통과"였고 그 도메인 목록을 공식 시나리오에서 매번 읽었다.

**인증 대상 도메인을 지금의 7개로 고정하고, `deployment`는 공식 Drill·트랙·개념·Drill Score에는 들어가되 인증 판정에는 넣지 않는다.** Drill Score는 공식 도메인에서 동적으로 계산되므로 상한이 늘고(940 → 1,000대), 티어 경계는 절대 점수라 그대로다.

**이유**: 인증은 저장하지 않고 매번 계산되는 판정이라, 공식 도메인이 늘면 이미 인증을 공유한 사용자(공개 검증 페이지 링크를 이력서에 붙였을 수 있다)가 **다음 조회부터 조용히 미인증**이 된다. 대안은 (1) 그대로 두어 소급 박탈을 받아들이기, (2) 인증 버전을 도입해 "v1 인증 = 7개, v2 = 8개"로 나누기, (3) 새 도메인을 공식이 아닌 마켓플레이스 시나리오로 두기였다. (1)은 공개 검증 링크의 신뢰를 깨고, (2)는 인증 화면·검증 페이지·조직 커리큘럼까지 버전 개념을 퍼뜨리며, (3)은 Drill Score·트랙·개념 숙련에서 빠져 "공식 콘텐츠"로서의 의미를 잃는다. 고정 목록은 코드 한 줄로 (2)의 효과를 얻는다.

**대가**: 인증이 플랫폼의 모든 공식 도메인을 대표하지 않게 된다(인증 화면에 "인증 대상 7개 도메인"을 명시). 인증 범위를 넓히려면 그때 (2) 인증 버전을 도입하고, 기존 인증은 v1로 남긴다.
