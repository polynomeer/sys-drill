# 챌린지 이벤트는 마이그레이션이 아니라 관리자 화면에서 만든다

기간 한정 챌린지([COMMUNITY_EXPANSION_PLAN.md](../COMMUNITY_EXPANSION_PLAN.md) C13)는 "이 공식 시나리오를 이 기간에"라는 정의 한 줄이다.

**`challenge_events` 행을 PLATFORM_ADMIN이 관리자 화면에서 만든다.** 시나리오 자체는 지금처럼 마이그레이션으로만 생긴다 — 이벤트는 기존 공식 시나리오를 가리킬 뿐 새 콘텐츠를 만들지 못한다.

**이유**: [ADR-0002](0002-content-via-migrations-not-admin-crud.md)는 콘텐츠를 관리자 CRUD 대신 마이그레이션으로 넣기로 했다 — 콘텐츠는 코드 리뷰를 거쳐야 하고 환경마다 같아야 하기 때문이다. 이벤트는 그 어느 쪽도 아니다: 날짜는 운영 일정이라 환경마다 달라야 하고(스테이징에서 미리 열어 볼 수 있어야 함), 시작 며칠 전에 정해지며, 배포 주기에 묶이면 "다음 주 월요일 시작"을 위해 배포를 해야 한다. 대안이었던 설정 파일(ADR-0006 방식)도 같은 배포 결합이 있다. 관리자 입력의 위험(잘못된 콘텐츠)은 이벤트가 시나리오 ID·제목·기간만 가지므로 작다.

**대가**: 이벤트 정의는 저장소에 기록이 남지 않는다(관리자 화면이 유일한 출처). 이벤트가 문제·채점까지 바꾸는 형태로 커지면 그 부분은 다시 마이그레이션 콘텐츠로 가야 한다.
