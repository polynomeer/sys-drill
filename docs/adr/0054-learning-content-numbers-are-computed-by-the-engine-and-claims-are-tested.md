# Learning 콘텐츠의 수치는 저장하지 않고 엔진이 계산하며, 서술의 방향은 테스트가 지킨다

Learning에 그림과 수치를 넣으면서(docs/LEARNING_DEEPENING_PLAN.md L12~L14) "Single-flight를 켜면 DB 읽기 부하가 4000%에서 400%로 준다" 같은 문장이 콘텐츠에 들어가기 시작했다. 콘텐츠는 마이그레이션으로 들어가고(ADR-0002), 같은 현상을 Drill과 랩은 규칙 엔진으로 계산한다(ADR-0047).

**결정**: 콘텐츠 블록 중 수치를 보여 주는 것(`numbers`, `system`)은 값을 저장하지 않고 도메인·인시던트 여부·`DesignTraits` 덮어쓰기만 저장한다. 페이지를 읽을 때 `ContentBlockService`가 엔진으로 before/after를 계산해 채운다. 본문이 주장하는 방향은 블록에 `claims`(지표, UP/DOWN/SAME)로 함께 저장하고, `ContentBlocksTest`가 모든 시드 블록의 claims를 엔진 결과와 대조한다.

**대안과 이유**: 수치를 콘텐츠에 직접 적으면 단순하지만, 엔진 수식이 바뀔 때(도메인 테스트와 함께 자주 바뀐다) Learning만 조용히 틀린 숫자를 보여 준다 — Drill에서 겪는 값과 Learning에서 읽은 값이 달라지는 것이 이 제품이 가장 피해야 할 어긋남이다. 수치만 엔진이 계산하고 서술 방향은 검증하지 않으면, 숫자는 맞는데 문장("지연도 줄어든다")이 틀리는 경우를 못 잡는다. 실제로 첫 콘텐츠를 쓰면서 초안의 "지연이 줄어든다"가 틀렸다는 것(DB가 여전히 포화라 P95·에러는 그대로)을 이 대조로 발견했다. claims는 사용자 예측을 채점하는 정답표가 아니라 콘텐츠 회귀 테스트라 ADR-0047의 "정답표를 저장하지 않는다"와 충돌하지 않는다.

**대가**: 콘텐츠 작성자는 숫자 대신 trait 덮어쓰기를 써야 하고, 엔진이 표현하지 못하는 현상(예: 복제 지연)은 수치 블록으로 쓸 수 없다 — 서술(text·callout)로만 다룬다. 페이지를 열 때마다 엔진을 몇 번 호출하지만 도메인 함수가 마이크로초 단위라 비용은 무시할 만하다.
