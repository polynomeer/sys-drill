# Marketplace scenarios join the same public pool as Flyway-seeded content instead of a separate namespace, and v1 ships with no payment or approval queue

`Scenario` already had `organizationId: UUID?` (null = public, set = org-scoped, [0024](0024-custom-scenarios-coexist-with-migration-content-and-scope-cut-to-design-only.md)). A marketplace-published scenario adds a second, independent nullable column — `creatorUserId` — and keeps `organizationId` null, so it lands in the exact same pool `ScenarioController`'s `GET /scenarios`/`GET /scenarios/{id}` and `SessionService.startSession` already serve. The alternative was a fully separate namespace (its own table or at least its own "is this playable" check), which would have needed its own session-start authorization path and its own dashboard-listing logic duplicating what `organizationId == null` already means. We took the reuse: zero changes to session start, and a marketplace scenario is discoverable both from the dedicated `/marketplace/scenarios` hub and from the exact same scenario list every user already sees on the dashboard. The cost is that "official" and "creator-authored" content are no longer distinguishable by which table or endpoint served them — a future reader inspecting `GET /scenarios` might assume every entry is Flyway-seeded reference content the way [0002](0002-content-via-migrations-not-admin-crud.md) implies. We mitigated this by always populating `creatorNickname` (null for official content) on both summary and detail responses, so the frontend can label community content without the backend needing a separate discovery path.

v1 ships with no payment and no revenue split, despite PRD.md naming a 70/30 creator/platform split as the long-term model — that split needs a real payment processor and a purchase/entitlement table, neither of which exists anywhere in this codebase yet (mirrors [0003](0003-no-real-authentication-in-mvp.md)'s "don't build the real version of X until X's value is validated" reasoning), and PRD.md itself scopes the split to "beyond MVP." Publishing also has no approval queue: any authenticated user's scenario goes live immediately, the same "smallest slice" choice [0024](0024-custom-scenarios-coexist-with-migration-content-and-scope-cut-to-design-only.md) made for organization-scoped custom scenarios. Both are easy to add later — a `priceCents`/purchases table, or a `PENDING` status gate before a scenario's `organizationId`/`creatorUserId` split takes effect — without touching the reuse decision above.
